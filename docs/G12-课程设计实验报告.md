# 1 实验目的与课程基线对照

## 1.1 实验目的

将企业园区访客管理从纸质登记搬到线上，打通「员工提预约 → 审核员审批 → 生成核验码 → 门岗核验入场 → 离场登记」的完整链路，在每个节点留下处理记录与状态审计；并围绕这套业务完成容器化打包、本地 Compose 编排、K8s 部署、发布/回滚、弹性伸缩与故障复盘，掌握云容器与集群管理的完整流程。

# 2 系统概述

## 2.1 业务流程

```
员工提交预约 ──→ 审核通过 ──→ 生成核验码 ──→ 门岗核验入场 ──→ 离场登记
   (∅→0)        (0→1)        (1→2)         (2→3)         (3→4)
      └──────────────┬──────────────┘
                      ↓ 驳回 / 取消
                 9 驳回/取消（终态）
```

## 2.2 三种角色

| 角色码 | 名称 | 定位 |
| --- | --- | --- |
| `EMPLOYEE` | 员工 | 发起预约、查看/取消本人预约 |
| `AUDITOR` | 审核员 | 审批本部门预约、生成核验码，兼门岗核验（数据范围受 `dept_id` 限制） |
| `ADMIN` | 管理员 | 全部权限，含用户/部门后台管理与全局统计 |

后端是唯一权限权威：`@RequireRole` 注解在拦截器拦角色，部门范围在 Service 层二次校验；越权返回 `403`，不返回空列表。

## 2.3 预约单状态机

| 值 | 名称 | 说明 |
| --- | --- | --- |
| 0 | 待审核 | 员工已提交，等审核 |
| 1 | 审核通过 | 审核员已通过，待生成核验码 |
| 2 | 待到访 | 核验码已生成，等访客到场 |
| 3 | 已到访 | 门岗已核验入场 |
| 4 | 已离开 | 离场登记完成，终态 |
| 9 | 驳回/取消 | 异常终态 |

允许流转：`0→{1,9}`、`1→{2,9}`、`2→{3,9}`、`3→{4}`；4、9 为终态。不在表内的转移（反向、跳级、终态复活）一律 `400 STATE_NOT_ALLOWED`。

每次状态变更在同一事务内完成：校验当前状态 → 带旧状态做乐观锁更新主单 → 写 `biz_status_change_log` → 写 `apply_process_record`；任一插入失败整事务回滚，不允许「状态变了但没日志」。

## 2.4 六张数据表

| 表名 | 说明 | 关键外键 |
| --- | --- | --- |
| `sys_department` | 部门表 | — |
| `sys_user` | 用户表（BCrypt 存密，停用不物理删除） | `dept_id → sys_department.id` |
| `visitor_apply` | 预约主单表 | `dept_id → sys_department.id`、`create_by → sys_user.id` |
| `visitor_record` | 到访离场登记表（一单最多一条） | `apply_id → visitor_apply.id`，唯一键 `uk_record_apply` |
| `apply_process_record` | 业务操作处理记录（只增不改） | `apply_id → visitor_apply.id` |
| `biz_status_change_log` | 状态变更审计日志（只增不改） | `apply_id → visitor_apply.id` |

## 2.5 技术架构

- **后端**：JDK 21、Spring Boot 3.5.16、MyBatis-Plus 3.5.17、jjwt 0.12.6、MySQL Connector/J、Spring Security Crypto（BCrypt）、Actuator、Validation、Lombok；HikariCP 连接池；日志输出到 stdout。
- **前端**：Vue 3.5、Vite 7、Vue Router 4、Pinia 3、Axios、Element Plus；路由守卫 + Axios 拦截器；含 mock 适配器，生产镜像 `VITE_USE_MOCK=false`。
- **数据**：MySQL 8.0（镜像 `mysql:8.0`，`utf8mb4`）。
- **部署**：Docker Compose 本地编排；k3s v1.28.2+k3s1 单节点集群，containerd 1.7.6；Ingress `g12.course.local`；后端 HPA（min 2 / max 4，CPU 60%）。

## 2.6 接口清单（28 业务接口 + 1 健康检查）

| 分组 | 数量 | 代表接口 |
| --- | --- | --- |
| 认证 `auth` | 3 | `POST /auth/login`、`GET /auth/me`、`POST /auth/logout` |
| 用户管理 `users` | 6 | 列表/详情/新增/修改/启停用/删除，全 `ADMIN` |
| 部门管理 `departments` | 4 | 列表/新增/修改/删除 |
| 预约 `applies` | 4 | 提交、我的预约、详情、取消 |
| 审核 `audit` | 5 | 待审核列表、通过、驳回、生成核验码、本部门列表 |
| 到访登记 `records` | 3 | 入场、离场、记录列表 |
| 统计 `stats` | 3 | 总览、近 N 天趋势、按部门分布 |
| 健康检查 | 1 | `GET /actuator/health`（基础设施，不计入业务接口数） |

统一响应 `{ "code": 200, "message": "ok", "data": ... }`；错误码：`400` 参数或业务错误、`401` 未认证、`403` 无权限、`404` 资源不存在、`409` 冲突。完整契约见 `docs/api.md`。

| TC-C5 | 后端重启后 token 仍有效 | 无状态 JWT，不依赖 session；拦截器复查账号状态 | 设计覆盖，未重启复测 |

## 6.4 数据一致性校验 SQL

```sql
-- 1) 状态 3/4 的单必须有到访记录（期望 0 行）
SELECT a.id, a.status FROM visitor_apply a
LEFT JOIN visitor_record r ON r.apply_id = a.id
WHERE a.status IN (3,4) AND r.id IS NULL;

-- 2) 状态 4 的单必须有离场时间（期望 0 行）
SELECT id FROM visitor_apply WHERE status = 4 AND leave_time IS NULL;

-- 3) 有审核动作的单，状态日志应包含 0→1 或 0→9（期望 0 行）
SELECT a.id FROM visitor_apply a
WHERE a.status IN (1,2,3,4,9) AND a.audit_time IS NOT NULL
  AND NOT EXISTS (SELECT 1 FROM biz_status_change_log l
                  WHERE l.apply_id = a.id AND l.from_status = 0);

-- 4) 状态 3/4 的单，日志链路应为 0→1→2→3(→4)（期望 0 行）
SELECT a.id, COUNT(l.id) AS cnt FROM visitor_apply a
LEFT JOIN biz_status_change_log l ON l.apply_id = a.id AND l.to_status IN (1,2,3)
WHERE a.status IN (3,4) GROUP BY a.id HAVING cnt <> 3;

-- 5) 统计口径核对
SELECT COUNT(*) FROM visitor_apply WHERE deleted = 0;
SELECT COUNT(*) FROM visitor_record WHERE DATE(checkin_time) = CURDATE();
SELECT COUNT(*) FROM visitor_record WHERE DATE(checkout_time) = CURDATE();
SELECT status, COUNT(*) FROM visitor_apply GROUP BY status;
```

## 9.2 故障复盘 INC-G12-001（F2 配置类）

- **现象**：前端页面能打开，但所有 `/api` 请求 502；后端健康检查同样 502。
- **根因**：`g12-backend` Service 的 selector 与 Pod 标签不一致，Endpoints 为空，nginx 连不上上游。
- **定位与修复**：先按 502 而非 404/504 判断方向；查 Endpoints 为空 → describe Service 比对 selector 与 Pod 标签 → 修正 selector，Endpoints 回填、服务恢复。
- 完整过程与六份证据见 `docs/incident-record.md`、`evidence/07-incident/`。

# 12 风险与应对

| 风险 | 应对 |
| --- | --- |
| 演示机无法直连镜像源 | 镜像 tar 本地导入节点 containerd；addon 离线清单入库 `k8s/addons` |
